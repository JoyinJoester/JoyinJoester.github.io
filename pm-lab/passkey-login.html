KNOWN FAILURE MODES
  • CONDITIONAL 需要安全上下文 + 可发现凭据（residentKey=required 建的那批）。用 discouraged 建的 key 不会出现在建议里。
  • SILENT 在没有凭据时立刻 NotAllowedError，这正是"无 UI 静默登录"的判定方式。
  • 限定 allowCredentials 却选了别的设备建的 id ⇒ NotAllowedError，容易被误读成"passkey 坏了"。
  • 没有后端：challenge 由本页生成、由本页比对。签名与 counter 未做服务端校验，counter 回退（克隆密钥检测）只能人工看趋势。
  • 反复点 GET 会累积多条同源凭据；某些管理器的建议列表会开始重复显示，这是它的去重策略问题，不是本站的。
